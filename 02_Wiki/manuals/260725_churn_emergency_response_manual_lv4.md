# 이탈 고객 긴급 우회 대응 매뉴얼: 회원가입 인증 코드 대기 구간

## 1. 개요
본 매뉴얼은 베타 서비스 회원가입 과정 중 '인증 코드 확인 대기' 구간에서 발생하는 높은 이탈률(35%)에 대응하고, 고객의 불편을 최소화하며 서비스 복귀를 유도하기 위한 CS 실무 지침입니다. Bitz(개발팀)와 협의하여 API 비동기 가입 절차 간소화를 진행 중입니다.

## 2. 주요 이탈 지점 및 원인
*   **이탈 지점**: 회원가입 시 인증 코드 확인 대기 화면
*   **이탈률**: 35% (가장 높은 이탈률)
*   **추정 원인**:
    *   인증 코드 전송 지연 (API 비동기 처리 지연)
    *   고객의 대기 시간 허용 범위 초과
    *   인증 실패 시 명확한 안내 부족

## 3. CS 긴급 우회 대응 프로토콜

### 3.1. 고객 문의 접수 시 응대
*   **공감 및 사과**: "회원가입 시 인증 코드 문제로 많이 불편하셨겠습니다. 현재 해당 구간에서 일부 고객님들이 불편을 겪고 계시며, 저희 개발팀에서 최우선으로 개선 작업을 진행 중입니다."
*   **문제 설명**: "인증 코드 전송 시스템의 일시적인 지연 문제로 확인됩니다."

### 3.2. 즉각적인 해결 방안 (CS 에이전트 조치)
1.  **재시도 안내**: "잠시 후 다른 네트워크 환경(Wi-Fi <-> 데이터)이나 다른 기기에서 다시 시도해 보시면 해결되는 경우가 있습니다."
2.  **수동 인증 지원**:
    *   고객의 가입 시도 이메일/전화번호를 확인합니다.
    *   CS 관리자 시스템을 통해 해당 고객의 가입 상태를 확인하고, **수동으로 인증 코드 재발송**을 시도합니다.
    *   (필요시) 고객 동의 하에 CS 에이전트가 직접 계정 생성을 지원하고, 생성된 계정 정보(임시 비밀번호 등)를 안전하게 전달합니다.
3.  **프리미엄 케어 제안**: "만약 계속 어려움을 겪으신다면, 고객님의 정보를 받아 저희가 직접 가입 절차를 도와드리는 '프리미엄 케어'를 제공해 드릴 수 있습니다. 이메일 주소나 전화번호를 알려주시면 바로 처리해 드리겠습니다."

### 3.3. 이탈 고객 복귀 유도 및 피드백
1.  **복귀 메일 발송**: 문제 해결 후, 이탈 유저 복귀 리드메일 티켓에 명시된 문구를 활용하여 고객에게 문제 해결 안내 및 서비스 재이용을 독려하는 메일을 발송합니다. (예: 추가 혜택 제공 등)
2.  **고객 피드백 기록**: 모든 관련 문의는 CS 티켓에 상세히 기록하고, `02_Wiki/decisions/` 경로에 백로그로 자산화합니다.
3.  **제품 개선 연계**: 기록된 고객 피드백은 Aegis(마스터)를 통해 Nova(기획) 및 Bitz(개발)에 전달하여, API 비동기 가입 절차 간소화 작업의 우선순위를 높이도록 요청합니다.

## 4. CS 시스템 동기화
*   본 매뉴얼은 CS 시스템 내 '긴급 대응 지침' 섹션에 업로드 및 전파됩니다.
*   모든 CS 에이전트는 본 매뉴얼 내용을 숙지하고, 실제 고객 응대에 적극적으로 활용합니다.
