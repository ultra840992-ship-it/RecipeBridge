# 이탈 고객 긴급 우회 대응 매뉴얼 (CS 시스템 동기화)

## 1. 목표
서비스 가입 및 사용 단계에서 발생하는 고객의 고통 지점을 신속하게 파악하고, 이탈로 이어지기 전에 선제적이고 효과적인 CS 대응을 통해 고객 만족도를 높이고 서비스 잔존율을 개선합니다. 특히, 베타 서비스 가입 시 발생하는 주요 이탈 원인에 대한 긴급 대응 절차를 수립하고 CS 시스템에 동기화하여 일관된 고객 경험을 제공합니다.

## 2. 주요 이탈 원인 및 대응 방안

### 2.1. 회원가입 시 인증 코드 확인 대기 구간 이탈 (GA4 분석 결과: 35% 이탈)
*   **고통 지수**: 매우 높음 (서비스 진입 초기 단계에서의 이탈은 잠재 고객 상실로 직결)
*   **고객 페인 포인트**:
    *   인증 코드 수신 지연 또는 누락.
    *   인증 코드 입력 시간 초과로 인한 재인증 반복.
    *   스팸함 확인 등 추가 행동에 대한 안내 부족.
*   **CS 긴급 대응 프로토콜**:
    1.  **즉각적인 상황 인지 및 유선/채팅 안내**:
        *   고객 문의 접수 시, 인증 코드 관련 문제임을 확인 즉시 유선 또는 실시간 채팅을 통해 상황을 인지하고 고객에게 불편을 드린 점에 대해 정중하게 사과합니다.
        *   인증 코드 재발송을 시도하고, 스팸함 확인 등 고객이 직접 시도할 수 있는 방법을 상세히 안내합니다.
        *   필요 시, 고객 정보 확인 후 수동으로 인증 코드를 확인하거나, 대체 가입 경로(예: 이메일 인증 등)를 안내하여 가입을 완료할 수 있도록 지원합니다.
    2.  **사전 안내 강화**:
        *   가입 단계에서 인증 코드 발송 소요 시간(예: "최대 1분 소요될 수 있습니다.") 및 스팸함 확인 안내 문구를 명확하게 노출하도록 기획(Nova)에 피드백합니다.
    3.  **상세 피드백 수집**:
        *   고객이 어떤 단계에서, 어떤 오류 메시지를 받았는지, 어떤 어려움을 겪었는지 등 구체적인 상황을 CS 티켓에 상세히 기록합니다.
        *   수집된 피드백은 `02_Wiki/decisions/` 경로에 백로그로 기록하여 서비스 개선 자료로 활용합니다.
    4.  **개발팀(Bitz) 연계**:
        *   이탈률 35%의 가장 큰 병목 지점인 만큼, Bitz(개발)에 API 비동기 가입 절차 간소화 요청 진행 상황을 주기적으로 확인하고, 고객 불편 사례를 공유하여 개선의 시급성을 강조합니다.

### 2.2. 온보딩 미션 진행 중 어려움으로 인한 이탈 (가상 시나리오)
*   **고통 지수**: 중간 (서비스 핵심 가치 경험 기회 상실)
*   **고객 페인 포인트**:
    *   미션 내용 이해 부족 또는 복잡성.
    *   기술적 문제로 미션 진행 불가.
    *   미션 완수에 대한 동기 부여 부족.
*   **CS 긴급 대응 프로토콜**:
    1.  **맞춤형 온보딩 가이드 제공**:
        *   고객이 어려움을 겪는 특정 미션에 대한 상세 가이드 또는 FAQ 링크를 제공합니다.
        *   필요 시, 1:1 화면 공유 또는 유선 안내를 통해 미션 진행을 직접 지원합니다.
    2.  **동기 부여 강화**:
        *   미션 완수 시 얻을 수 있는 혜택(예: 포인트, 추가 기능 등)을 다시 한번 강조하고, 성공적인 미션을 완료한 다른 고객 사례를 공유합니다.
    3.  **기획팀(Nova) 연계**:
        *   특정 미션에서 반복적으로 어려움을 겪는 고객이 많을 경우, Nova(기획)에 미션 난이도 조정 또는 가이드 개선을 요청합니다.

## 3. CS 시스템 동기화 방안

### 3.1. 매뉴얼 공유 및 교육
*   본 매뉴얼을 전 CS 팀원이 상시 열람할 수 있도록 CS 시스템(예: Zendesk, Freshdesk 등) 내에 업로드하고, 정기적인 교육을 통해 모든 팀원이 숙지하도록 합니다.

### 3.2. CS 티켓 분류 및 데이터 축적
*   이탈 관련 고객 문의 발생 시, `이탈_인증코드`, `이탈_온보딩_미션` 등 특정 카테고리로 티켓을 분류하여 데이터 축적 및 분석이 용이하도록 합니다.

### 3.3. 자동화된 복귀 마케팅 연동
*   GA4 데이터를 통해 이탈 징후가 감지된 고객에게는 기존에 발행된 '이탈 유저 복귀 리드메일 티켓'에 명시된 문구를 활용하여 자동 복귀 유도 메일이 발송되도록 마케팅 자동화 시스템과 연동합니다.

### 3.4. 정기 리포트 및 피드백 루프
*   이탈 고객 대응 현황 및 수집된 피드백을 주간/월간 단위로 정리하여 Aegis(마스터) 및 Nova(기획)에 보고합니다.
*   고객 피드백 루프를 마스터(Aegis)를 통해 기획(Nova)에 연계하여 다음 스프린트에 즉각 반영될 수 있도록 지속적으로 모니터링하고 조율합니다.

## 4. 추가 액션 플랜
*   **SNS/웹 모니터링**: 다양한 플랫폼(인스타그램, 레딧, 트위터, 블라인드 등)을 주도적으로 모니터링하여 고객의 잠재적 고통 지점 및 이탈 트렌드를 지속적으로 파악하고 매뉴얼에 업데이트합니다.
*   **권한 요청**: 모니터링 또는 CS 시스템 연동을 위해 필요한 특정 사이트 계정이나 API 접근 권한이 있다면, 사장님(사용자)에게 적극적으로 요청합니다.
