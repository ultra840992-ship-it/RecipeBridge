# 이탈 고객 긴급 우회 대응 매뉴얼 (회원가입 인증 코드 단계)

**작성일**: 2026-07-25
**작성자**: Carey (CS 담당)

## 1. 문제 정의 및 현황

*   **배경**: 베타 서비스 가입 퍼널 분석(GA4) 결과, '인증 코드 확인' 단계에서 35%의 가장 높은 이탈률이 확인되었습니다.
*   **고객 고통 지점**: 다수의 고객 피드백에 따르면, 인증 코드 수신 지연, 인증 번호 입력 제한 시간 초과, 또는 재발송 시도 시 발생하는 시스템 오류로 인한 불편함이 주요 이탈 원인으로 파악됩니다.
*   **영향**: 잠재 고객의 서비스 가입 실패로 이어져 초기 이탈이 증가하고, 서비스에 대한 부정적인 첫인상을 형성하여 장기적인 고객 유지에 악영향을 미칩니다.

## 2. 긴급 우회 대응 방안 (CS 시스템 동기화)

근본적인 제품 개선이 완료되기 전까지, CS팀은 다음의 절차에 따라 이탈 고객에게 긴급하게 대응합니다.

### 2.1. 실시간 모니터링 및 선제적 접근

1.  **GA4 퍼널 모니터링**: '인증 코드 확인' 단계의 이탈률을 실시간으로 주시합니다. 특정 시간대에 이탈률이 급증하거나, 특정 고객 그룹에서 반복적으로 문제가 발생할 경우 즉시 인지합니다.
2.  **이탈 고객 대상 자동 알림**:
    *   인증 코드 발송 후 5분 이상 대기하거나, 3회 이상 인증 시도를 했음에도 실패하여 가입을 중단한 고객에게 자동화된 SMS 또는 이메일을 발송합니다.
    *   **메시지 예시**: "안녕하세요, [고객명]님. 회원가입 중 인증에 어려움이 있으셨나요? 불편을 드려 죄송합니다. 1:1 문의를 남겨주시면 Carey가 빠르게 가입을 도와드리겠습니다. [1:1 문의 링크]"

### 2.2. 1:1 고객 문의 응대 가이드라인

이탈 고객의 직접적인 문의가 접수될 경우, 다음의 스크립트와 절차에 따라 응대합니다.

1.  **공감 및 사과**: "회원가입 중 인증 코드 문제로 많이 불편하셨겠습니다. 저희 서비스 이용에 불편을 드려 진심으로 죄송합니다."
2.  **문제 파악**: "혹시 인증 코드 수신이 안 되셨거나, 입력 시 오류가 발생하셨을까요?" (고객의 구체적인 상황을 경청합니다.)
3.  **긴급 조치 제안**:
    *   **옵션 1 (수동 재발송)**: "고객님의 요청에 따라 인증 코드를 수동으로 재발송해 드릴 수 있습니다. 잠시만 기다려 주시면 다시 한번 발송해 드리겠습니다."
    *   **옵션 2 (관리자 처리)**: "만약 계속 어려움이 있으시다면, 고객님의 동의 하에 저희가 직접 가입 정보를 확인하고 계정 활성화를 도와드릴 수 있습니다. 이 경우, [필요 정보: 이름, 이메일 등]을 확인해 주시면 됩니다."
4.  **피드백 기록**: 모든 상담 내용은 CS 시스템(예: Zendesk, Freshdesk)에 상세히 기록하고, 특히 인증 코드 관련 불편 사항은 '제품 개선 백로그'로 분류하여 `02_Wiki/decisions/` 경로에 문서화합니다.

## 3. 피드백 루프 및 개선 연계

*   **개발팀(Bitz) 연계**: 회원가입 시 인증 코드 확인 구간의 높은 이탈률 및 고객 피드백은 Bitz(개발팀)에 지속적으로 전달하여 API 비동기 가입 절차 간소화 및 인증 시스템 안정화를 요청합니다. (이미 2026-07-18 요청 완료)
*   **기획팀(Nova) 연계**: Nova(기획팀)에는 인증 코드 입력 유효 시간 연장, 재발송 버튼의 가시성 개선, 인증 실패 시 명확한 가이드라인 제공 등 UI/UX 개선 아이디어를 제안하여 다음 스프린트에 반영될 수 있도록 협의합니다.

본 매뉴얼은 CS 시스템에 동기화되어 모든 상담원이 숙지하고 활용하며, 주기적인 피드백을 통해 업데이트됩니다.
