# 이탈 고객 긴급 우회 대응 매뉴얼 (회원가입 인증 코드 대기 구간 이탈)

**작성일**: 2026-07-25
**작성자**: Carey (CS 담당)
**버전**: 1.0

## 1. 개요 및 목표

본 매뉴얼은 베타 서비스 가입 과정 중 '인증 코드 확인 대기' 단계에서 발생하는 높은 이탈률(GA4 분석 결과 35%)에 대응하기 위한 CS 긴급 우회 대응 지침을 명시합니다. 고객의 불편을 최소화하고, 이탈 고객의 서비스 재가입을 효과적으로 유도하여 궁극적으로 이탈률을 낮추는 것을 목표로 합니다.

## 2. 배경 및 문제점

*   **문제 지점**: GA4 가상 퍼널 1차 추적 결과, 회원가입 시 '인증 코드 확인 대기' 구간에서 가장 높은 35%의 이탈률이 확인되었습니다.
*   **원인 추정**: 인증 코드 전송 지연, 고객의 대기 시간 불만, 시스템 오류 등으로 인한 것으로 분석됩니다.
*   **개선 요청**: Bitz(개발)팀에 API 비동기 가입 절차 간소화를 요청하여 근본적인 개선을 진행 중입니다.

## 3. CS 대응 지침

### 3.1. 이탈 고객 감지 및 분류

*   **자동 감지**: GA4 이탈 지표 및 CS 시스템 내 '인증 코드 대기 중 이탈' 태그가 부여된 고객 리스트를 주기적으로 모니터링합니다.
*   **수동 확인**: 고객 문의 중 인증 코드 관련 불편 사항 접수 시, 해당 고객을 이탈 가능성이 높은 고객으로 분류합니다.

### 3.2. 긴급 복귀 유도 메일 발송

이탈 고객에게는 다음과 같은 단계를 거쳐 복귀 유도 메일을 발송합니다.

*   **1차 (자동화)**:
    *   이탈 감지 즉시, 사전에 기획된 "이탈 유저 복귀 리드메일" 템플릿을 사용하여 자동 발송합니다. (Memory: 이탈 유저 복귀 리드메일 티켓 발행 완료)
    *   **메일 내용 핵심**: 가입 과정에서의 불편 사과, 시스템 개선 노력 안내, 재시도 독려, 가입 재시도 바로가기 링크 포함.
*   **2차 (수동/개인화)**:
    *   1차 메일 발송 후 24시간 이내 복귀가 없는 고객 중, CS 에이전트가 판단하기에 재유도 가능성이 높은 고객에게는 개인화된 메일을 수동 발송합니다.
    *   **메일 내용 핵심**:
        *   "안녕하세요, [고객명]님. 가입 과정에서 불편을 드려 다시 한번 죄송합니다."
        *   "현재 인증 코드 전송 시스템 개선 작업이 진행 중이며, 최대한 빠르게 안정화될 수 있도록 노력하고 있습니다."
        *   "혹시 스팸함 확인, 네트워크 환경 점검 등 몇 가지 간단한 확인 후 다시 시도해 보시면 도움이 될 수 있습니다."
        *   "번거로우시더라도, 다음 링크를 통해 다시 한번 가입을 시도해 주시면 감사하겠습니다: [가입 재시도 링크]"
        *   "만약 계속해서 어려움이 있으시다면, 이 메일에 회신 주시거나 [CS 연락처]로 연락 주시면 저희 CS팀이 직접 가입을 도와드리겠습니다."
        *   "필요시 이메일 인증 외에 다른 인증 방법 (예: 휴대폰 번호 인증)으로의 전환을 안내해 드릴 수도 있습니다."

### 3.3. 고객 문의 응대 가이드라인

인증 코드 관련 고객 문의 접수 시, 다음 스크립트를 활용하여 응대합니다.

*   "고객님, 회원가입 시 인증 코드 문제로 불편을 드려 정말 죄송합니다. 현재 해당 부분에 대한 시스템 개선 작업이 진행 중이라 일시적인 지연이 발생할 수 있습니다."
*   "우선, 혹시 스팸함에 인증 메일이 들어가 있지는 않은지 확인해 주실 수 있을까요? 또한, 네트워크 환경을 잠시 점검해 보시는 것도 도움이 될 수 있습니다."
*   "만약 위 방법으로도 해결되지 않으신다면, 저희가 직접 가입 절차를 지원해 드리거나, 다른 인증 방법으로 전환하여 가입을 도와드릴 수 있습니다. 어떻게 도와드릴까요?"

## 4. CS 시스템 동기화 및 피드백 루프

*   **CS 시스템 연동**:
    *   `'인증 코드 대기 중 이탈'` 고객 자동 분류 태그를 CS 시스템에 추가합니다.
    *   긴급 복귀 유도 메일 템플릿을 등록하고, 자동 및 수동 발송 기능을 연동합니다.
    *   인증 코드 문제 관련 FAQ 및 대응 스크립트를 CS 시스템 내에 업데이트합니다.
*   **피드백 기록**: 인증 코드 관련 고객 불만 사항 발생 시, 상세 내용을 CS 티켓에 기록하고, `02_Wiki/decisions/` 경로에 피드백 문서를 추가하여 제품 개선 백로그로 연계합니다. (Memory: Bitz에게 API 비동기 가입 절차 간소화 요청 결정)
*   **마스터 연계**: 수집된 고객 피드백은 Aegis(마스터)를 통해 Nova(기획)에 연계되어 다음 스프린트에 즉각 반영되도록 합니다.
