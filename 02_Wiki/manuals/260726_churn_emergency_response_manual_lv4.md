# 이탈 고객 긴급 우회 대응 매뉴얼 (회원가입 인증 코드 단계)

## 1. 개요
본 매뉴얼은 베타 서비스 회원가입 과정 중 '인증 코드 확인 대기' 단계에서 발생하는 높은 고객 이탈률(GA4 분석 결과 35%)에 대응하기 위해 CS팀이 즉각적으로 수행할 수 있는 긴급 우회 대응 절차를 명시합니다. 고객의 불편을 최소화하고, 재가입을 유도하며, 궁극적으로 서비스 가입 완료율을 높이는 것을 목표로 합니다.

## 2. 주요 이탈 지점 및 원인 (GA4, 고객 피드백 기반)
*   **이탈 지점**: 회원가입 시 '인증 코드 확인 대기' 구간
*   **이탈률**: 35% (가장 높은 이탈률 기록)
*   **근본 원인 (추정)**:
    *   인증 코드 전송 지연 또는 실패
    *   인증 코드 입력 시간 초과로 인한 재시도 불편
    *   복잡하거나 불명확한 인증 절차 안내

## 3. 제품 개선 연계 사항
*   **개발팀(Bitz) 요청**: API 비동기 가입 절차 간소화 요청 완료 (2026-07-18)
    *   현재 개발팀에서 근본적인 해결책을 마련 중입니다. 개선 완료 전까지 CS팀의 선제적 대응이 중요합니다.

## 4. CS 긴급 우회 대응 절차

### 4.1. 이탈 고객 식별 및 초기 대응
1.  **이탈 고객 식별**: GA4 퍼널 분석 도구 또는 CS 시스템 내 실시간 알림을 통해 '인증 코드 대기' 단계에서 이탈한 고객을 신속하게 식별합니다.
2.  **신속한 초기 메시지 발송**: 이탈 후 5분 이내에 이탈 유저 복귀 리드메일 템플릿을 활용하여 고객에게 따뜻한 위로와 함께 문제 해결 의지를 전달합니다.
    *   **메일 템플릿 주요 내용**: "가입 중 불편을 드려 죄송합니다. 혹시 인증 코드 수신에 어려움이 있으셨을까요? 저희가 도와드리겠습니다."

### 4.2. 문제 진단 및 해결 가이드 제공
1.  **상황 파악**: 고객과의 소통을 통해 정확히 어떤 문제로 이탈했는지 조심스럽게 파악합니다.
2.  **기본 문제 해결 안내**:
    *   "스팸함/스팸 메시지함을 확인해 주시겠어요?"
    *   "네트워크 환경(Wi-Fi/모바일 데이터)을 변경하여 다시 시도해 보시겠어요?"
    *   "휴대폰 재부팅 후 다시 시도해 보시겠어요?"
    *   "다른 연락처로 인증을 시도해 보시는 것도 방법입니다."
    *   "잠시 후 다시 시도해 주시면 원활하게 진행될 수 있습니다."
3.  **대체 인증 수단 제안 (필요시)**:
    *   고객이 동의할 경우, CS팀에서 고객 정보 확인 후 수동으로 인증 절차를 지원하거나, 임시 계정 발급 후 서비스 체험을 유도합니다. (반드시 보안 정책 및 개인정보 보호 규정 준수)

### 4.3. 피드백 수집 및 시스템 연계
1.  **상세 피드백 기록**: 고객과의 모든 대화 내용과 문제 해결 과정을 CS 티켓에 상세히 기록합니다. 특히, 고객이 직접 언급한 불편 사항이나 개선 아이디어를 명확히 기록합니다.
2.  **백로그 추가**: 수집된 고객 피드백 중 제품 개선에 필요한 사항은 `02_Wiki/decisions/` 경로에 백로그로 추가하여 서비스 개선 우선순위에 반영되도록 합니다. (예: `260726_signup_churn_feedback_auth_code.md`)
3.  **제품팀(Nova) 및 개발팀(Bitz) 연계**: Aegis를 통해 Nova(기획)와 Bitz(개발)에 정기적으로 고객 피드백을 공유하여 제품 개선 작업에 반영될 수 있도록 합니다.

## 5. CS 담당자 유의사항
*   **고객 중심 사고**: 항상 고객의 입장에서 생각하고, 불편함에 깊이 공감하는 태도를 유지합니다.
*   **정중하고 따뜻한 어조**: 전문 CS 컨설턴트로서 정중하고 따뜻한 어조로 고객을 설득하고 안내합니다.
*   **적극적인 문제 해결 의지**: 고객의 문제를 해결하기 위해 적극적으로 노력하는 모습을 보여줍니다.
*   **보안 및 개인정보 보호**: 고객의 개인정보 및 보안 관련 사항은 철저히 준수합니다.
